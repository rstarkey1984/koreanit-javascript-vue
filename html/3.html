1. DOM(Document Object Model)

DOM은 브라우저가 HTML을 해석해서 만든 문서 객체 구조다.

  • HTML 파일은 그대로 화면에 그려지지 않는다
  • 브라우저는 HTML을 읽어 DOM 객체 트리를 만든다
  • 화면은 DOM을 기준으로 렌더링된다
  • JavaScript는 DOM 객체를 통해서만 화면에 접근한다
HTML 파일
→ 브라우저가 해석
→ DOM 객체 트리 생성
→ 화면 렌더링

2. DOM 기본 확인

실습 가이드

📄 파일명: 2-dom-basic.html

<!DOCTYPE html>
<html>
<body>

<h1>DOM 테스트</h1>
<p>이 문장은 DOM 요소다</p>

<script>
  console.log(document);
  console.log(document.body);
</script>

</body>
</html>

준비

  • 브라우저에서 파일을 연다
  • 개발자도구(F12)를 열고 Console 탭을 켠다

Step 1. document 객체 확인

  1. 파일을 새로고침한다
  2. 콘솔에 document가 출력되는지 확인한다

체크 포인트

  • 객체 형태로 길게 출력되면 정상
  • 이 객체가 현재 웹페이지 전체를 대표한다

Step 2. document.body 확인

  1. 콘솔에 document.body가 출력되는지 확인한다
  2. <body>...</body> 형태가 보이는지 확인한다

체크 포인트

  • <body> 영역이 DOM 객체로 잡히면 성공

실습 정리

  • 브라우저에는 항상 document 객체가 존재한다
  • document.body는 화면에 보이는 영역이다
  • JavaScript는 document를 통해서만 화면에 접근한다

3. HTML 요소 선택

DOM을 제어하려면 먼저 원하는 요소를 정확히 선택해야 한다.

실습 가이드

📄 파일명: 3-dom-select.html

<!DOCTYPE html>
<html>
<body>

<h1 id="title">제목</h1>
<p class="item">첫 번째</p>
<p class="item">두 번째</p>

<script>
  const title = document.getElementById("title");
  const item = document.querySelector(".item");

  console.log(title);
  console.log(item);
</script>

</body>
</html>

Step 1. id로 요소 선택

  1. getElementById("title")를 실행한다
  2. 콘솔에 <h1 id="title">가 출력되는지 확인한다

체크 포인트

  • 태그가 보이면 선택 성공

Step 2. CSS 선택자로 요소 선택

  1. querySelector(".item")를 실행한다
  2. 첫 번째 <p> 요소가 출력되는지 확인한다

체크 포인트

  • querySelector는 조건에 맞는 요소 하나만 선택한다

Step 3. 선택 실패 상황 확인

  1. id를 일부러 틀려본다
  2. 콘솔 출력이 null인지 확인한다

체크 포인트

  • null은 에러가 아니라 선택 실패 신호다
  • 오타 또는 script 위치를 점검해야 한다

실습 정리

  • DOM 조작의 시작은 요소를 변수에 담는 것이다
  • 콘솔에 태그가 보이면 성공
  • null이면 선택 실패다

4. DOM 내용과 스타일 변경

DOM 객체의 값을 바꾸면 화면은 즉시 바뀐다.

<script>

  title.textContent = "변경 후";
  title.style.color = "red";
</script>

</body>
</html>

Step 1. 텍스트 변경 확인

  1. 페이지를 새로고침한다
  2. 제목 텍스트가 바뀌는지 확인한다

체크 포인트

  • DOM 값 변경 즉시 화면 반영

Step 2. 스타일 변경 확인

  1. 글자 색상이 변경되는지 확인한다

체크 포인트

  • JavaScript 한 줄로 UI가 변경된다

Step 3. 값 바꿔보기

  1. 텍스트 내용을 다른 문장으로 변경한다
  2. 색상을 다른 색으로 변경한다

체크 포인트

  • 새로고침 후에도 변경 내용이 반영된다

실습 정리

  • DOM 값 변경은 화면 변경으로 이어진다
  • JavaScript는 DOM을 통해 UI를 직접 제어한다

5. 이벤트와 DOM 연결

JavaScript는 이벤트가 발생했을 때 DOM을 변경한다.

실습 가이드

📄 파일명: 5-event-dom.html

<!DOCTYPE html>
<html>
<body>

<h1 id="title">대기 중</h1>
<button id="btn">클릭</button>

<script>
  const title = document.getElementById("title");
  const button = document.getElementById("btn");

  button.addEventListener("click", function () {
    title.textContent = "클릭됨";
    title.style.color = "blue";
  });
</script>

</body>
</html>

Step 1. 이벤트 실행 확인

  1. 페이지를 새로고침한다
  2. 버튼을 클릭한다

체크 포인트

  • 클릭하기 전에는 화면이 변하지 않는다
  • 클릭했을 때만 변경된다

Step 2. 이벤트 내부 코드 수정

  1. 텍스트 내용을 다른 문장으로 바꾼다
  2. 색상을 변경한다

체크 포인트

  • 이벤트가 발생했을 때만 코드가 실행된다

실습 정리

  • 이벤트는 코드 실행의 출발점이다
  • 클릭 → 함수 실행 → DOM 변경 → 화면 변경

6. UI 실행 흐름 완성

핵심은 데이터(상태) 와 화면(DOM) 을 JavaScript 코드가 어떻게 연결하는지 이해하는 것이다.

이 실습에서 확인할 것

  • 화면에 보이는 값은 데이터의 결과다
  • 데이터가 바뀌지 않으면 화면도 바뀌지 않는다
  • 데이터가 바뀌어도 DOM을 갱신하지 않으면 화면은 그대로다

즉,

데이터 변경과 화면 반영은 서로 다른 단계다.

실습 가이드

📄 파일명: 6-ui-flow.html

<!DOCTYPE html>
<html>
<body>

<p id="count">0</p>
<button id="btn">증가</button>

<script>
  const countEl = document.getElementById("count");
  const button = document.getElementById("btn");
  let count = 0;

  button.addEventListener("click", function () {
    count = count + 1;
    countEl.textContent = count;
  });
</script>

</body>
</html>

Step 1. 상태 변화 확인

  1. 버튼을 여러 번 클릭한다
  2. 숫자가 증가하는지 확인한다

체크 포인트

  • 데이터(count)와 화면(countEl)이 연결된다

Step 2. 데이터 변경 주석 처리

  1. count = count + 1;을 주석 처리한다
  2. 클릭 시 화면이 바뀌는지 확인한다

체크 포인트

  • 데이터가 바뀌지 않으면 화면도 바뀌지 않는다

Step 3. 화면 업데이트 주석 처리

  1. countEl.textContent = count;를 주석 처리한다
  2. 클릭 시 숫자 변화 여부를 확인한다

체크 포인트

  • 데이터 변경과 화면 반영은 다른 단계다

Step 4. 화면에 없는 DOM을 새로 만들어보기 (createElement)

지금까지는 이미 존재하는 DOM만 수정했다. 이제는 화면에 없는 DOM 구조를 직접 만들어서 붙이는 방법을 확인한다.

이번 Step에서는 li를 만들기 전에, 먼저 ul부터 만든다.

// 1) ul 요소를 새로 만든다
const ul = document.createElement("ul");

// 2) li 요소를 새로 만든다
const li = document.createElement("li");
li.textContent = "새로 만든 항목";

// 3) li를 ul에 먼저 붙인다
ul.appendChild(li);

// 4) 완성된 ul을 document.body에 붙인다
document.body.appendChild(ul);

체크 포인트

  • createElement는 화면에 없는 요소를 메모리에서 생성한다
  • DOM 구조는 부모 → 자식 순서로 만들어야 한다
  • appendChild로 DOM 트리에 붙이는 순간 화면에 나타난다

실습 정리

  • 기존 DOM 수정: textContent, style
  • 새 DOM 생성: createElement
  • 화면 반영의 기준은 항상 DOM 트리에 붙였는가다

7. 서버와 데이터 통신

핵심 개념 한 줄 요약

서버에서 오는 데이터는 텍스트 → JSON → JavaScript 객체 → DOM → 화면 이 순서를 반드시 거친다.

반드시 기억해야 할 핵심 포인트

  1. 네트워크로 전달되는 것은 항상 텍스트(TEXT) 다.
  2. fetch()의 결과는 데이터가 아니라 응답 객체(response) 다.
  3. 서버 응답은 먼저 문자열(text) 로 받아진다.
  4. 문자열은 JSON 규칙으로 변환해야 객체로 사용할 수 있다.
  5. 데이터가 있어도 DOM에 붙이지 않으면 화면에 나오지 않는다.

서버 응답 처리 흐름

fetch 요청
→ response 객체
→ response.text()  (문자열)
→ JSON.parse()     (객체/배열)
→ DOM 생성
→ appendChild()
→ 화면 출력

실제 개발에서는 보통 아래 방식으로 사용한다.

const data = await response.json();

JSON의 정체

  • JSON은 데이터 전송을 위한 텍스트 규칙이다
  • 실행되는 코드가 아니다
  • 데이터 구조만 표현한다

특징

  • 전체는 객체 { }
  • 키는 항상 문자열
  • 값은 숫자, 문자열, boolean, 객체, 배열 가능
  • 함수, 변수 선언은 존재하지 않는다

JSON과 JavaScript 객체의 차이

구분 JSON JavaScript 객체
위치 네트워크 / 파일 메모리
목적 전송·저장 실행·처리
형태 문자열 규칙 실제 객체
실행 불가능 가능

실습 가이드 — 서버 데이터 → 화면 출력

📄 파일명: 7-fetch-posts.html

실습 목표

  • 서버 응답이 문자열이라는 것을 확인한다
  • JSON → JavaScript 객체 변환을 이해한다
  • 서버 데이터를 DOM으로 옮겨 화면에 출력한다

기본 틀

<!DOCTYPE html>
<html lang="ko">
<body>

  <h2>게시글 목록</h2>
  <button id="load">불러오기</button>
  <ul id="list"></ul>

  <script>
    const button = document.getElementById("load");
    const list = document.getElementById("list");

    async function loadPosts() {
      // Step별 코드 작성
    }

    button.addEventListener("click", loadPosts);
  </script>

</body>
</html>

Step 1. 서버 응답을 텍스트로 확인

async function loadPosts() {
  const response = await fetch("https://jsonplaceholder.typicode.com/posts");
  const text = await response.text();
  console.log(text);
}

체크 포인트

  • 콘솔에 긴 문자열이 출력된다
  • 객체처럼 보이지만 문자열(TEXT) 이다
  • 화면은 아직 비어 있어도 정상이다

Step 2. 텍스트를 JSON → 객체로 변환

async function loadPosts() {
  const response = await fetch("https://jsonplaceholder.typicode.com/posts");
  const text = await response.text();
  const posts = JSON.parse(text);

  console.log(posts);
}

체크 포인트

  • posts는 배열이다
  • posts[0].title 접근 가능
  • JavaScript가 구조를 이해한다

Step 3. response.json() 사용

async function loadPosts() {
  const response = await fetch("https://jsonplaceholder.typicode.com/posts");
  const posts = await response.json();

  console.log(posts);
}

체크 포인트

  • Step 2와 결과가 동일하다
  • 실무에서는 이 방식을 기본으로 사용한다

Step 4. 서버 데이터를 DOM으로 출력 (핵심)

async function loadPosts() {
  const response = await fetch("https://jsonplaceholder.typicode.com/posts");
  const posts = await response.json();

  list.innerHTML = "";

  for (let post of posts) {
    const li = document.createElement("li");
    li.textContent = post.title;
    list.appendChild(li);
  }
}

체크 포인트

  • 버튼 클릭 시 <li> 목록이 화면에 나타난다
  • appendChild 실행 순간 화면이 갱신된다

Step 5. 확인 실험

  1. list.appendChild(li)를 주석 처리
  2. 버튼 클릭
  3. 화면에 아무 것도 나오지 않는지 확인
  4. 주석 해제 후 다시 실행

체크 포인트

  • 데이터 ≠ 화면
  • DOM에 붙이지 않으면 화면에 표시되지 않는다

실습 정리

  • 서버 응답은 항상 텍스트다
  • JSON은 데이터 전송 규칙이다
  • response.json()으로 객체 변환
  • 화면 출력은 DOM 조작의 결과다
  • appendChild가 없으면 화면도 없다

3일차 핵심 정리

  • 브라우저는 HTML을 그대로 화면에 그리지 않고 DOM 객체 트리로 만든다

  • JavaScript는 화면을 직접 그리지 않고, DOM을 통해 간접 제어한다

  • document는 현재 웹페이지 전체를 대표하는 최상위 객체다

  • DOM 조작의 시작은 요소 선택이다(getElementById, querySelector)

  • DOM의 값이나 스타일을 바꾸면 화면은 즉시 변경된다

  • 이벤트는 코드 실행의 출발점이다 (이벤트 → 함수 실행 → DOM 변경)

  • 서버에서 오는 데이터는 객체가 아니라 텍스트(TEXT) 다

  • JSON은 데이터를 주고받기 위한 텍스트 규칙이다

  • 서버 데이터는 DOM으로 옮겨야만 화면에 표시된다
