1. DOM 직접 제어의 한계

Day 3까지 우리는 JavaScript로 DOM을 직접 제어했다.

title.textContent = count;
title.style.color = "red";

이 방식은 간단한 화면에서는 문제가 없지만,

화면이 복잡해질수록 다음 문제가 생긴다.

DOM 직접 제어의 문제점

  • 같은 DOM 조작 코드가 반복된다
  • 데이터 상태와 화면 변경 코드가 섞인다
  • 화면이 많아질수록 수정이 어렵다

DOM을 직접 만지는 방식은 규모가 커질수록 유지보수가 힘들다.

2. DOM 직접 제어 실습 (문제 체험)

실습 4-1

파일명: 4-1-dom-hard.html

<!DOCTYPE html>
<html>
<body>

<p id="count">0</p>
<button id="btn">증가</button>

<script>
  let count = 0;
  const countEl = document.getElementById("count");
  const button = document.getElementById("btn");

  button.addEventListener("click", function () {
    count = count + 1;
    countEl.textContent = count;
    countEl.style.color = count % 2 === 0 ? "red" : "blue";
  });
</script>

</body>
</html>

생각해볼 점

  • 화면이 10개라면?
  • 상태가 5개라면?
  • 이 로직을 모든 곳에 복사해야 한다

3. 도구의 진화

3-1. jQuery

jQuery는 DOM 조작을 쉽게 만든 도구다.
  • DOM 선택과 조작을 간단하게 함
  • 코드량 감소
  • 하지만 DOM 직접 제어 방식은 그대로
jQuery의 핵심은 "편하게 DOM을 만지자"였다.

3-2. Vue / React

Vue와 React는 DOM을 직접 만지지 않는다.
  • 화면 상태를 데이터로 관리
  • 데이터가 바뀌면 화면이 자동으로 맞춰짐
  • DOM은 프레임워크가 대신 관리

핵심 차이 정리

구분방식
jQueryDOM → 화면
Vue / React상태 → 화면

개발자는 무엇을 보여줄지(상태) 만 신경 쓴다.

4. Vue 맛보기 (CDN 방식)

Vue는 상태 기반 UI 프레임워크다.

실습 4-3

파일명: 4-3-vue-cdn.html

<!DOCTYPE html>
<html>
<body>

<div id="app">
  <p>{{ count }}</p>
  <button @click="count++">증가</button>
</div>

<script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>
<script>
  const { createApp } = Vue;

  createApp({
    data() {
      return {
        count: 0
      };
    }
  }).mount('#app');
</script>

</body>
</html>

여기서 중요한 점

  • DOM을 직접 건드린 코드
  • 데이터(count)만 변경 ⭕
  • 화면은 Vue가 알아서 갱신

5. 상태 → 화면 흐름 체험

실습 4-4

파일명: 4-4-vue-state.html

<!DOCTYPE html>
<html>
<body>

<div id="app">
  <input v-model="message">
  <p>{{ message }}</p>
</div>

<script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>
<script>
  const { createApp } = Vue;

  createApp({
    data() {
      return {
        message: "안녕 Vue"
      };
    }
  }).mount('#app');
</script>

</body>
</html>

관찰 포인트

  • 입력값 변경
  • DOM 직접 조작 없음
  • 상태 변경 → 화면 자동 반영
