JavaScript 데이터와 이벤트의 기본 구조

강의 목표

이 날의 목적은 문법 암기가 아니라, JavaScript 코드가 어떤 구조와 흐름으로 동작하는지를 이해하는 것이다.

  • 값과 변수, 연산자, 제어문의 역할을 설명할 수 있다
  • 객체와 배열로 데이터를 구조화할 수 있다
  • 함수와 이벤트의 관계를 설명할 수 있다

1. 값과 변수 (Value & Variable)

JavaScript는 값을 만들고, 변수에 연결하고, 그 값을 사용하는 언어다.

이 장에서는 JavaScript에서 가장 중요한 개념인 값(Value) 과 변수(Variable) 를 구분해서 이해한다.

1-1. 값(Value)이란?

값은 JavaScript가 계산하고, 비교하고, 출력할 수 있는 실제 데이터다.

10
"안녕 JavaScript"
true

값은 다음과 같은 특징을 가진다.

  • 스스로 의미를 가진다
  • 연산의 대상이 된다
  • 화면에 출력될 수 있다

1-2. 값의 자료형(Type)

JavaScript에서 자료형(타입)은 변수가 아니라 값의 종류를 의미한다.

타입 설명 예시
number 숫자 10, 3.14
string 문자열 "hello"
boolean 참/거짓 true, false
null 의도적으로 비어 있는 값 null
undefined 아직 값이 없는 상태 undefined
object 여러 값을 묶은 타입 {}, []

JavaScript에서는 변수에 타입이 있는 것이 아니라, 값에 타입이 있다.

1-3. 변수(Variable)란?

변수는 값을 저장하는 공간이 아니라, 값에 이름을 붙이는 식별자다. 

let x = 10;

이 코드는 다음 의미를 가진다.

  1. x라는 이름을 만든다
  2. 숫자 값 10을 평가한다
  3. 그 값을 x에 바인딩한다

1-4. 변수와 값의 관계

JavaScript에서는 변수는 재사용되고, 바인딩된 값만 바뀔 수 있다.

let x = 10;
x = "10";

위 코드에서:

  • 변수 이름 x는 변하지 않는다
  • x에 바인딩된 값만 변경된다

이것이 JavaScript에서

"변수의 타입이 바뀐다"라고 느껴지는 이유다.

하지만 정확히 말하면

변수는 그대로이고, 값의 타입이 바뀐다.

1-5. 값 중심으로 코드 읽기

다음 코드를 변수가 아니라 값 기준으로 해석해보자.

let a = 10;
let b = a;
a = 20;

실행 흐름:

  1. 값 10이 평가되어 a에 바인딩된다
  2. a의 값 10이 b로 복사되어 바인딩된다
  3. a에 새 값 20이 바인딩된다

👉 b는 여전히 값 10을 가진다.

중요

  • 이 예제는 원시값(number) 이다
  • 원시값은 변수 간에 공유되지 않는다

객체(Object)는 다르게 동작한다.

let o1 = { test: 1 };
let o2 = o1;
o1.test = 2;
console.log(o2.test); // 2
  • 객체는 값 자체가 아니라 참조(reference) 가 복사된다
  • 그래서 같은 객체를 참조하면 내부 변경이 공유된다

1-6. 변수 선언 키워드 비교

JavaScript에서 var, let, const는 타입이 아니라 변수를 만드는 방식(선언 키워드) 이다.

변수 선언은 크게 두 가지를 결정한다.

  • 재선언 가능 여부 (같은 이름으로 다시 선언 가능?)
  • 재할당 가능 여부 (값을 다시 넣을 수 있나?)
키워드 재선언 재할당 특징
var 가능 가능 예전 방식, 사용 비추천
let 불가 가능 값이 바뀌는 변수
const 불가 불가 값이 바뀌지 않는 변수(상수처럼 사용)

1-7. var가 비추천인 이유(핵심만)

var는 같은 이름으로 다시 선언이 가능해서, 실수로 코드를 덮어써도 오류가 나지 않는 문제가 생긴다.

var x = 10;
var x = 20; // 오류가 나지 않는다
console.log(x); // 20

정리

  • var는 코드 규모가 커질수록 “실수 감지”가 어렵다
  • 그래서 현대 JavaScript에서는 let/const를 기본으로 사용한다

1-8. let은 ‘재할당 가능한 변수’

let score = 10;
score = 20; // 가능

체크 포인트

  • 값이 바뀌어야 하는 경우에 let을 사용한다

1-9. const는 ‘재할당 불가’

const pi = 3.14;
pi = 3.14159; // 오류

체크 포인트

  • const는 다시 대입(재할당) 이 불가능하다
  • 기본값은 const로 두고, 꼭 바뀌어야 하는 경우만 let으로 바꾸는 습관이 좋다

1-10. (중요) const 객체/배열은 내부 값 변경이 가능하다

const는 변수가 가리키는 대상 자체를 바꾸지 못한다(재할당 불가) 는 의미다.

하지만 객체/배열은 “하나의 값 안에 여러 값을 담는 구조”라서, 그 내부 값은 바뀔 수 있다.

const user = { name: "kim" };
user.name = "lee"; // 가능 (내부 값 변경)

// user = { name: "park" }; // 불가능 (재할당)

const list = [1, 2, 3];
list.push(4); // 가능 (내부 변경)

// list = [9, 9, 9]; // 불가능 (재할당)

체크 포인트

  • const는 “내부 변경 금지”가 아니라 “재할당 금지”다

(보충 설명) JavaScript에는 왜 변수 이름 규칙이 중요할까?

JavaScript에서는 변수 자체에 타입 정보가 없다. 타입은 변수에 붙는 것이 아니라 값에 붙는다.

let x = 10;
x = "10";

위 코드에서:

  • 변수 이름 x는 변하지 않는다
  • x가 가리키는 값의 타입만 바뀐다

그래서 JavaScript에서는 코드만 보고 이 변수에 어떤 값이 들어있는지 알기 어렵다.

이 문제를 보완하기 위해, JavaScript에서는 변수 이름이 값의 성격을 설명하는 역할을 하게 된다.

let data;        // 무엇인지 알기 어렵다
let userName;    // 문자열일 가능성이 높다
let userAge;     // 숫자일 가능성이 높다
let isLogin;     // true / false 값

이런 이유로 JavaScript에서는 의미가 드러나는 변수 이름 규칙이 매우 중요하다.

정리

  • JavaScript에서는 변수에 타입이 없다
  • 타입은 값에 붙는다
  • 그래서 변수 이름이 곧 의미 설명서 역할을 한다

2. 연산자 (Operator)

연산자는 값을 계산하거나 비교해 새로운 값을 만들어낸다.

연산자는 결과로 또 다른 값을 만든다. 이 결과 값이 변수에 저장되거나, 제어문의 조건으로 사용된다.

산술 연산자

10 + 5
10 - 3
10 * 2
10 / 2
10 % 2

문자열과 숫자

"10" + 5   // "105"
10 + "5"   // "105"

비교 / 논리 연산자

10 > 5
10 === 10
true && false

체크 포인트

  • 논리 연산은 true/false를 조합해 또 다른 true/false를 만든다

Step 5. 연산 결과를 변수에 저장

  1. let result = 10 + 5; 처럼 결과를 변수에 저장해 출력한다.
  2. 문자열 결합 결과도 변수에 저장해 출력한다.

체크 포인트

  • “연산 → 결과 값 생성 → 변수에 연결” 흐름이 보이면 통과

정리

  • 비교 연산의 결과는 항상 true 또는 false다
  • 논리 연산은 true / false를 조합해서 또 다른 결과를 만든다

3. 제어문 (Control Flow)

제어문은 코드의 실행 흐름을 제어하는 문법이다.

연산자(특히 비교/논리)의 결과로 나온 true/false 값을 이용해 "어떤 코드를 실행할지", "몇 번 반복할지"를 결정한다.

조건문 (if)

let score = 80;

if (score >= 60) {
  console.log("합격");
}

반복문 (for)

for (let i = 0; i < 3; i++) {
  console.log(i);
}

Step 1. if의 조건을 바꿔가며 실행 확인

  1. score를 80으로 두고 실행한다 → "합격"이 출력되어야 한다
  2. score를 50으로 바꾸고 실행한다 → 출력이 없어야 한다

체크 포인트

  • if 블록은 조건이 true일 때만 실행된다

Step 2. else 추가 (조건이 false일 때)

  1. 아래 형태로 else를 추가한다.
  • 합격이면 "합격"
  • 아니면 "불합격"
  1. score를 80, 50으로 바꿔가며 실행한다

체크 포인트

  • if/else는 둘 중 하나만 실행된다

Step 3. for 기본 반복 이해

  1. for (let i = 0; i < 5; i++)로 0~4 출력
  2. 조건을 i < 3으로 바꿔 0~2 출력

체크 포인트

7. 데이터와 함수의 관계

JavaScript에서는 데이터(값) 와 그 데이터를 처리하는 함수가 분리되어 존재하기도 하고, 함께 묶여 존재하기도 한다.

7-1. 데이터와 함수가 분리된 경우

let count = 0;

function increase() {
  count = count + 1;
}

increase();

이 구조의 특징:

  • count는 데이터
  • increase는 데이터를 처리하는 함수
  • 함수가 외부에 있는 데이터에 의존한다

문제점:

  • 어떤 함수가 어떤 데이터를 바꾸는지 한눈에 보이지 않는다
  • 데이터가 많아질수록 관리가 어려워진다

7-2. 데이터와 함수를 함께 묶은 경우 (객체)

const counter = {
  count: 0,
  increase: function () {
    this.count = this.count + 1;
  }
};

counter.increase();

이 구조의 특징:

  • count → 상태(데이터)
  • increase() → 동작(함수)
  • 같은 객체 안에서 함께 관리된다

이렇게 하면 “이 데이터는 이 함수들이 다룬다” 라는 관계가 코드 구조 자체에 드러난다

7-3. 왜 객체 안에 데이터와 함수를 함께 두는가?

이유는 크게 세 가지다.

  1. 관련된 것끼리 묶기 위해

    • count를 바꾸는 함수는 counter 안에 있다

  2. 역할을 명확하게 하기 위해

    • counter는 “카운트를 관리하는 역할”을 가진다

  3. 코드를 읽기 쉽게 만들기 위해

    • counter.increase() → “counter의 기능 중 하나를 실행한다”는 의미가 바로 보인다

7-4. 이 개념이 앞으로 어디로 이어지는가

이 구조는 이후에 배우는 모든 것의 기초가 된다.

  • 객체(Object)
  • DOM 요소 (element.style, element.addEventListener)
  • Vue의 data / methods
  • React의 state / handler
  • 클래스(Class)

모두 같은 생각에서 출발한다.

상태(데이터) + 동작(함수)을 하나로 묶어서 관리한다

한 문장 요약

JavaScript에서는 데이터만 따로 두지 않고, 그 데이터를 다루는 함수와 함께 묶어 관리할 수 있고, 그 묶음이 바로 객체(Object)다. 

const counter = {
  value: 0,
  increase: function () {
    this.value = this.value + 1;
    console.log(this.value);
  }

체크 포인트

  • 이벤트 + 제어문 + 상태가 하나로 연결된다

정리

  • 클릭 같은 사용자 행동이 코드 실행의 시작점이 된다는 걸 확인했다
  • 이벤트가 발생할 때마다 함수가 실행된다는 걸 경험했다
  • 이벤트를 통해 값이 바뀌고, 그 결과가 화면에 반영되는 걸 봤다
  • 조건을 추가해서 잘못된 동작을 막을 수 있다는 것도 확인했다

2일차 핵심 정리

  • JavaScript는 값 중심 언어다 → 타입은 변수에 붙지 않고 값에 붙는다 → 변수는 값을 담는 상자가 아니라 값을 가리키는 이름이다

  • 연산자는 계산·비교를 통해 새로운 값을 만든다

  • 제어문(if / for) 은 → 연산 결과(true / false)를 기준으로 → 코드 실행 흐름을 제어한다

  • 객체 / 배열은 데이터를 구조화하는 방법이다 → 객체: 의미 있는 대상 → 배열: 순서 있는 목록

  • 함수는 실행할 코드를 묶어둔 단위다 → 정의와 호출은 다르며 ()가 실행 신호다

  • 이벤트는 → “언제 함수가 실행될지”를 결정하는 실행 트리거다
