1. DOM 직접 제어의 한계

Day 3까지 우리는 JavaScript로 DOM을 직접 제어했다.

title.textContent = count;
title.style.color = "red";

이 방식은 작은 화면에서는 문제가 없지만,
화면이 조금만 복잡해져도 관리 비용이 급격히 증가한다.

DOM 직접 제어의 문제점

  • 같은 DOM 조작 코드가 여러 곳에서 반복된다
  • 데이터(상태) 변경 코드와 화면(DOM) 변경 코드가 섞인다
  • 화면 구조가 바뀌면 JavaScript 코드도 함께 수정해야 한다

👉 DOM을 직접 만지는 방식은 규모가 커질수록 유지보수가 어렵다.

2. DOM 직접 제어 실습

실습 목표

  • "상태가 바뀌어도 화면은 자동으로 바뀌지 않는다"는 사실을 체험한다
  • 상태 로직과 화면 로직이 섞이기 시작하는 지점을 직접 확인한다

실습가이드

📄 파일명: 2-dom-hard.html

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8" />
  <title>DOM 직접 제어 실습</title>
</head>
<body>

  <p id="count">0</p>
  <button id="btn">증가</button>

  <script>
    let count = 0;

    const countEl = document.getElementById("count");
    const button = document.getElementById("btn");

    button.addEventListener("click", handleClick);

    function handleClick() {
      // Step 코드가 이 함수 안에 추가된다
    }
  </script>

</body>
</html>

사전 체크

  • 버튼 클릭 시 handleClick 함수가 실행되는지만 확인한다
  • 아직 화면 변화는 없다

Step 1. 상태 값 증가 처리

handleClick 함수 안에 아래 코드를 추가한다.

count = count + 1;

체크 포인트

  • 클릭할 때마다 count 값은 증가한다
  • 화면 숫자는 여전히 0이다
  • 상태와 화면은 자동으로 연결되지 않는다

Step 2. 숫자 화면 반영

아래 코드를 handleClick 함수 안에 추가한다.

countEl.textContent = count;

체크 포인트

  • 상태 변경 결과를 직접 DOM에 반영해야 한다
  • 화면 갱신 책임이 개발자에게 있다

Step 3. 화면 스타일 변경

아래 코드를 handleClick 함수 안에 추가한다.

if (count % 2 === 0) {
  countEl.style.color = "red";
} else {
  countEl.style.color = "blue";
}

체크 포인트

  • 상태 값에 따라 화면 스타일을 직접 제어한다
  • 상태 로직 + 화면 로직이 한 함수에 섞이기 시작한다

실습 정리

  • 데이터가 바뀌어도 화면은 자동으로 바뀌지 않는다
  • 화면 변경을 위해 항상 DOM을 직접 조작해야 한다
  • 로직이 커질수록 코드가 빠르게 복잡해진다

👉 이 구조가 프레임워크 등장 배경이다

3. 도구의 진화

3-1. jQuery

jQuery는 DOM 조작을 쉽게 만든 도구다.

  • DOM 선택과 조작을 간결한 문법으로 제공
  • 코드량 감소
  • 하지만 DOM 직접 제어 구조는 그대로 유지된다

jQuery 실습

📄 파일명: 3-jquery-basic.html

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8" />
  <title>jQuery 기본 실습</title>
</head>
<body>

  <p id="count">0</p>
  <button id="btn">증가</button>

  <script src="https://code.jquery.com/jquery-3.7.1.min.js"></script>
  <script>
    let count = 0;

    $("#btn").on("click", handleClick);

    function handleClick() {
      // Step 코드 추가
    }
  </script>

</body>
</html>

Step 1. 상태 증가

count = count + 1;

Step 2. 화면 반영

$("#count").text(count);

Step 3. 스타일 변경

if (count % 2 === 0) {
  $("#count").css("color", "red");
} else {
  $("#count").css("color", "blue");
}

체크 포인트

  • 문법은 편해졌지만 구조는 동일하다
  • 상태 변경 → DOM 직접 수정 흐름은 변하지 않는다

3-2. Vue / React

Vue와 React는 DOM을 직접 만지지 않는다.

  • 화면 기준은 DOM이 아니라 상태(State)
  • 상태가 바뀌면 화면은 자동으로 갱신된다
  • DOM 관리는 프레임워크가 담당한다
구분 흐름
jQuery DOM → 화면
Vue / React 상태 → 화면

4. Vue 맛보기 (CDN 방식)

실습 목표

  • Vue가 DOM을 직접 제어하지 않는 방식을 체감한다
  • "상태만 바꿨는데 화면이 바뀐다"는 경험을 한다
  • DOM 조작 코드가 사라지는 구조를 확인한다

실습가이드

📄 파일명: 4-vue-cdn.html

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8" />
  <title>Vue CDN 실습</title>
</head>
<body>

  <div id="app">
    <p>{{ count }}</p>
    <button @click="increase">증가</button>
  </div>

  <script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>
  <script>
    const { createApp } = Vue;

    createApp({
      data() {
        return {
          count: 0
        };
      },
      methods: {
        increase() {
          this.count++;
        }
      }
    }).mount('#app');
  </script>

</body>
</html>

Step 1. Vue가 관리할 화면 영역 이해

  • <div id="app"> 영역을 Vue가 전담 관리한다
  • 이 영역 안에서는 DOM을 직접 건드리지 않는다

체크 포인트

  • document.getElementById가 없다
  • addEventListener가 없다

Step 2. 상태(State) 정의

  • data() 함수에서 count 상태를 정의한다
  • 이 값이 화면의 기준이 된다

체크 포인트

  • 화면의 숫자는 DOM이 아니라 count 값에서 나온다
  • 상태는 JavaScript 객체일 뿐이다

Step 3. 화면과 상태 연결

  • {{ count }}는 상태를 화면에 출력한다
  • DOM 조회 코드 없이 값이 표시된다

체크 포인트

  • 출력 대상 DOM을 직접 선택하지 않는다
  • "이 값이 어디에 표시되는지"를 Vue가 알고 있다

Step 4. 이벤트와 상태만 연결

  • 버튼 클릭 시 increase() 메서드 실행
  • 메서드 안에서는 this.count++만 수행

체크 포인트

  • 화면을 바꾸는 코드가 없다
  • 상태만 바꿨는데 화면이 자동으로 바뀐다

실습 정리

  • Vue에서는 DOM을 직접 조작하지 않는다
  • 상태(State)가 화면의 유일한 기준이다
  • 화면 갱신 책임을 프레임워크가 대신 가진다

5. 상태 → 화면 흐름 체험

실습 목표

  • 입력값, 이벤트, 화면 갱신이 자동으로 연결되는 구조를 체험한다
  • 상태 하나가 여러 화면에 동시에 반영되는 것을 확인한다

실습가이드

📄 파일명: 5-vue-state.html

<!DOCTYPE html>
<html lang="ko">
<head>
  <meta charset="UTF-8" />
  <title>Vue 상태 실습</title>
</head>
<body>

  <div id="app">
    <input v-model="message" />
    <p>{{ message }}</p>
    <p>글자 수: {{ message.length }}</p>
  </div>

  <script src="https://unpkg.com/vue@3/dist/vue.global.js"></script>
  <script>
    const { createApp } = Vue;

    createApp({
      data() {
        return {
          message: ""
        };
      }
    }).mount('#app');
  </script>

</body>
</html>

Step 1. 입력과 상태 연결

  • <input> 요소에 v-model을 사용한다
  • 입력값이 자동으로 message 상태에 저장된다

체크 포인트

  • 키보드 이벤트 코드를 작성하지 않는다
  • 입력과 상태 연결을 Vue가 처리한다

Step 2. 상태 출력

  • {{ message }}로 상태를 그대로 출력한다
  • 동일한 상태를 여러 곳에서 사용한다

체크 포인트

  • DOM 접근 코드가 전혀 없다
  • 같은 상태가 여러 화면에 동시에 반영된다

Step 3. 상태 기반 계산 출력

  • message.length를 화면에 출력한다
  • 별도의 계산 이벤트가 없다

체크 포인트

  • 상태가 바뀔 때마다 자동으로 다시 계산된다
  • 화면 갱신 로직이 없다

Step 4. 동작 관찰

  • 입력창에 글자를 입력하며 화면 변화를 확인한다

체크 포인트

  • 이벤트 리스너 없음
  • DOM 조회 없음
  • 상태 → 화면 흐름이 자동으로 유지된다

실습 정리

  • 입력, 이벤트, 화면 갱신을 직접 연결하지 않는다
  • 상태 하나가 여러 UI를 동시에 결정한다
  • UI 로직이 단순해지고 예측 가능해진다

Day 4 정리

  • DOM 직접 제어는 규모가 커질수록 한계가 명확해진다
  • 프레임워크는 편의가 아니라 구조적 해결책이다
  • Vue는 상태 중심 사고방식을 제공한다
